## Bulk download and retransmissions

```
$ nstat -n ; curl -so /dev/null -w '%{http_code} %{size_download} %{speed_download}\n' https://proof.ovh.net/files/10Mb.dat ; nstat TcpInSegs TcpExtTCPDSACKOldSent
200 10485760 17870641
#kernel
TcpInSegs                       7804               0.0
```

`nstat` omits zero counters, so `TcpExtTCPDSACKOldSent` is 0.

| | v0.2.5 (`docs/smoke-2026-11-18.md`) | v0.3.0 |
|---|---|---|
| DSACK duplicates | 42137 (84% of received segments) | 0 |
| TcpInSegs for 10 MB | 49954 | 7804 |
| Throughput | 9.1 MB/s | 17.9 MB/s |

The QueryPerformanceCounter stack clock removes the spurious retransmissions entirely and roughly doubles throughput. This confirms the root cause found in the Linux reproduction (`docs/superpowers/specs/2026-11-18-gvproxy-hires-clock-design.md`) on a real Windows host. PASS.
